# 配置

Dashboard 与 Agent 的启动参数都可以用环境变量设置：变量名为 `SSS_` 加参数名大写、`-` 换成 `_`，例如 `--trusted-proxies` 对应 `SSS_TRUSTED_PROXIES`。命令行显式传入的参数优先于环境变量；环境变量取值无效（如布尔参数写成 `yes`）时程序直接报错退出。

站点标题、上报间隔等运行期设置不在启动参数中，而是在后台修改，保存后立即生效。

## Dashboard

子命令：

| 子命令 | 说明 |
|---|---|
| `serve` | 启动面板服务，不写子命令时默认执行 |
| `reset-password` | 为 `admin` 生成新的随机密码并打印，已登录的会话全部失效 |
| `disable-captcha` | 关闭登录验证码，用于验证码配置有误无法登录时；Dashboard 正在运行时需重启后生效 |
| `version` | 显示版本 |

参数：

| 参数 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `--listen` | `SSS_LISTEN` | `:8900` | 监听地址 |
| `--data-dir` | `SSS_DATA_DIR` | `./data` | 数据目录，数据库文件为其中的 `sss.db`；`reset-password` 也按它定位数据库 |
| `--trusted-proxies` | `SSS_TRUSTED_PROXIES` | 空 | 可信反向代理的 IP 或 CIDR，逗号分隔。为空时不信任 `X-Forwarded-For`，客户端 IP 取连接地址 |
| `--admin-password` | `SSS_ADMIN_PASSWORD` | 空 | 首次初始化（数据库中还没有用户）时 `admin` 的密码；留空则随机生成并打印到日志。之后再设置不会生效 |
| `--log-level` | `SSS_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `--log-file` | `SSS_LOG_FILE` | 空 | 日志文件路径；留空只输出到标准输出。设置后同时输出到标准输出与文件，文件按 10 MB 轮转，保留 5 份、30 天 |

Docker 镜像已设置 `SSS_LISTEN=:8900`、`SSS_DATA_DIR=/app/data`、`TZ=Asia/Shanghai`。月流量周期按 Dashboard 所在时区计算。

示例：

```bash
sss-dashboard --listen 127.0.0.1:8900 --data-dir /var/lib/sss --trusted-proxies 127.0.0.1
SSS_DATA_DIR=/var/lib/sss sss-dashboard reset-password
```

## Agent

子命令：`run`（默认）、`version`。

配置可以来自 YAML 文件、环境变量或命令行参数，优先级：**命令行 > 环境变量 > YAML > 默认值**。

| YAML 键 | 参数 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|---|
| — | `--config` | `SSS_CONFIG` | 空 | 配置文件路径，见下方查找顺序 |
| `dashboard` | `--dashboard` | `SSS_DASHBOARD` | 空（必填） | Dashboard 地址，以 `http://` 或 `https://` 开头，如 `https://status.example.com`。Agent 连接 `<地址>/api/agent/ws`，`https` 自动使用 `wss` |
| `id` | `--id` | `SSS_ID` | 空（必填） | 后台创建服务器后得到的 ID |
| `secret` | `--secret` | `SSS_SECRET` | 空（必填） | 服务器密钥 |
| `detect_country` | `--detect-country` | `SSS_DETECT_COUNTRY` | `true` | 启动时与之后每 6 小时通过 Cloudflare trace 探测国家代码（用于显示国旗，后台填写了国家代码时以后台为准）与公网 IPv4 / IPv6 地址（用于状态页与后台的 IPv4 / IPv6 标记）；关闭后两者都不探测。探测直连 Cloudflare，不使用系统代理（`HTTPS_PROXY` 等），以免得到代理的出口地址；只能经代理出网时国家代码与 IP 都会探测失败，可在后台手动填写国家代码 |
| `log_level` | `--log-level` | `SSS_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `log_file` | `--log-file` | `SSS_LOG_FILE` | 空 | 日志文件路径，规则同 Dashboard |

上报间隔、网卡与挂载点过滤不在 Agent 配置中，由 Dashboard 在连接建立后下发，后台修改后立即推送给在线的 Agent。

### 配置文件查找顺序

1. 指定了 `--config`（或 `SSS_CONFIG`）时只读取该文件，文件不存在则报错。
2. 未指定时依次查找当前工作目录的 `./sss-agent.yaml`、`/etc/sss/sss-agent.yaml`，使用第一个存在的文件。
3. 都不存在时使用默认值，此时 `dashboard`、`id`、`secret` 必须通过参数或环境变量提供。

示例（与 `configs/sss-agent.yaml.example` 一致）：

```yaml
dashboard: "https://status.example.com"
id: "your-server-id"
secret: "your-secret"
detect_country: true
log_level: "info"
log_file: ""
```

安装脚本生成的配置位于 Linux `/etc/sss/sss-agent.yaml`、Windows `%ProgramFiles%\sss-agent\sss-agent.yaml`（Windows 额外设置了 `log_file` 为安装目录下的 `logs\agent.log`）。

## 后台设置

「设置」页的站点选项：

| 选项 | 默认值 | 说明 |
|---|---|---|
| 站点标题 | `Simple Server Status` | 显示在顶栏与浏览器标题；留空保存时恢复默认 |
| 公开显示价格 | 关闭 | 开启后未登录访客也能看到价格、币种与付费周期；登录后始终可见。到期日不受此项影响 |
| 默认上报间隔（秒） | `2` | 范围 1–60。新建或编辑服务器时「上报间隔」留空则使用此值（保存时写入该服务器，之后修改默认值不影响已有服务器） |
| 安装脚本地址 | `https://github.com/ruanun/simple-server-status/releases/latest/download` | 后台生成安装命令时使用的脚本下载前缀，需以 `http://` 或 `https://` 开头，末尾的 `/` 会被去掉 |
| 公告 | 空 | 显示在状态页顶部，支持换行，`http(s)://` 网址自动转为链接；不超过 1000 个字符，留空不显示 |

Dashboard 为正式发布版本时，若「安装脚本地址」保持默认，生成的命令会改用该版本的 Release 地址并追加 `--version`；改为其他地址时只追加 `--version`。「安装脚本地址」可改为自建镜像地址，要求该地址下能直接下载 `install-agent.sh` 与 `install-agent.ps1`（生成的命令为 `<地址>/install-agent.sh`、`<地址>/install-agent.ps1`）。注意脚本本身仍从 GitHub Release 下载 Agent 归档，目标机器需要能访问 GitHub。

同一页还提供修改密码（新密码至少 8 位，修改后其他已登录会话失效）以及导出 / 导入 JSON。导入时站点设置被文件覆盖，ID 相同的服务器被覆盖，其余新增。

### 通知

「设置」页的「通知」区块统一配置 Webhook / Telegram 渠道，以及哪些事件与提醒需要推送；单台服务器可通过「不发送通知」（见下文「服务器字段」）跳过全部推送，隐藏服务器不受影响、照常通知。

通知是事件之上的一层：事件（离线、高负载、重启、IP 变化）按「检测规则」记录，与是否配置渠道无关（见下文「事件」）；通知只决定是否把事件推送出去，并可以有自己的条件，例如离线满 1 分钟就记为事件，满「离线超过」设定的分钟数才推送。到期与流量是根据服务器配置安排的提醒，不记为事件。

渠道：Webhook 地址留空表示不启用；Telegram 需要同时填写 Bot Token 与 Chat ID，二者之一为空则不启用。通知语言默认 `zh-CN`，可切换为 `en-US`，决定通知标题与正文使用的语言。

各项均可独立开关：

| 规则 | 触发条件 | 恢复通知 | 默认 | 取值范围 |
|---|---|---|---|---|
| 离线 / 恢复 | 离线事件持续超过 N 分钟 | 推送过离线通知的，恢复在线时通知，附带离线时长 | 开，3 分钟 | 1–1440 分钟 |
| 持续高负载 / 恢复 | 高负载事件开始（阈值见「检测规则」），CPU / 内存 / 硬盘分别通知 | 推送过的，该项回落到阈值以下时通知 | 开 | — |
| 服务器重启 | 重启事件 | — | 开 | — |
| 公网 IP 变化 | IP 变化事件 | — | 开 | — |
| 即将到期 | 距到期不超过 D 天 | 无；每个到期日只提醒一次 | 开，7 天 | 1–90 天 |
| 月流量超阈值 | 设有配额且本周期用量达到 P% | 无；每个计费周期只提醒一次 | 开，90% | 1–100% |

「发送测试」按钮使用表单当前值（无需先保存）同步向已启用的渠道各发一条测试消息，分别显示成功或失败原因。

每个事件只决定一次是否推送，结果随事件保存：渠道启用之前就已开始的事件、静音服务器的事件、对应开关关闭时发生的事件都不推送，之后配置渠道、取消静音或打开开关也不会补发。Dashboard 重启前已在进行中的离线不再推送离线通知；重启前已推送过离线通知的，恢复时仍会推送恢复通知。事件通知由发送队列重试（见 [API - 通知](api.md#通知webhook--telegram)），全部渠道最终仍失败的记为推送失败，不再重试，之后也不推送对应的恢复通知；「发生」通知还在发送时事件已经结束的，等它发送成功后再推送恢复通知。

到期与流量提醒每 30 秒检查一轮，为一次性提醒：任一已启用渠道投递成功后才记为「已提醒」并持久化，重启后不会对同一到期日 / 计费周期重复提醒；投递中视为已提醒以避免重复入队，若全部渠道投递失败则撤销该标记，下一轮检查重新提醒。修改到期日后按新的到期时间重新计算，可能再次提醒。

### 检测规则

「设置」页的「检测规则」决定哪些状况记为事件，不论是否配置通知渠道都会记录：

| 规则 | 默认 | 取值范围 |
|---|---|---|
| 持续高负载：CPU / 内存 / 硬盘阈值 | 各 90% | 1–100% |
| 持续高负载：按最近多少分钟的平均值判断 | 5 分钟 | 1–10 分钟 |

离线（满 60 秒）、服务器重启、公网 IP 变化没有可调参数，始终记录。

### 事件

后台「事件」页（`/admin/events`）展示事件与通知记录两类历史，均可按服务器筛选、分页（每页 50 条），事件还可按类型筛选；网址中的 `?tab=`、筛选与分页参数会同步，便于刷新与分享。

事件分两种：离线、高负载有开始和结束，进行中的标记「进行中」；重启、IP 变化只有发生时间。

- **离线**：Agent 离线持续满 60 秒才记录一条（检查间隔 30 秒），避免短暂抖动产生记录；记录的起止时间以 Dashboard 视角为准，包含面板本身停机时段（面板重启后继续跟踪重启前未结束的记录：期间已恢复在线的据此补上结束时间，仍离线的保持进行中，不会重新计时）。未结束的记录在列表中标记「进行中」。
  - Dashboard 启动后有 2 分钟宽限期：期间只结束已有记录，不新建记录，给 Agent 留出重连时间，避免面板重启后每台服务器都多出一条离线记录。宽限期结束后仍离线的服务器照常新建记录，开始时间仍取最后一次上报（可能早于面板停机），因此跨越面板停机的真实离线也会被记录，停机时段计入时长。
- **高负载**：Dashboard 每 30 秒按「检测规则」计算 CPU、内存、硬盘最近若干分钟的平均值，任一项达到阈值即开始对应的事件，各自开始、各自结束；详情为阈值与事件期间平均值的峰值。离线期间不判断，已开始的高负载事件保持进行中，恢复上报后继续判断。窗口内少于 2 个数据点时不判断，Dashboard 重启后会等数据攒够再开始。
- **重启**：由 Agent 上报的运行时长推算开机时间（以 Dashboard 时间为准，不受服务器时钟影响），每次连接后的第一次上报与上次记录的开机时间比较，晚 2 分钟以上记为一次重启，事件时间为开机时间。首次连接只记录开机时间。
- **IP 变化**：Agent 每次连接时上报公网 IPv4 / IPv6，与上次不同即记录，详情为新旧地址；任一方为空（探测失败）不算变化。
- **通知记录**：每条通知（事件触发的通知、到期与流量提醒、「发送测试」）在每个渠道上记一条，重试不另记，以最终结果为准，可展开查看标题、正文与失败原因；「发送测试」产生的记录不关联具体服务器。面板退出时未能发出的记为失败，原因「退出时未能发送」；进程被强制结束时遗留的「发送中」记录会在下次启动时按同样方式记为失败。
- 两类记录都保留 90 天，到期自动清理（进行中的事件保留）。
- 事件只在后台展示；详情页「最近离线」仅展示该服务器最近 10 条离线记录（公开接口），列表下方附注「时间以面板记录为准，包含面板自身停机时段」。「设置 - 通知」中点击「发送测试」后，结果下方会出现「查看通知记录」链接，跳转到事件页的通知记录标签。
- 删除服务器时会同时删除其事件与通知记录；删除与检测并发时可能残留的记录由每小时的清理任务一并删除。

## 服务器字段

后台「服务器」页新建 / 编辑弹窗分四组。

**基本**

| 字段 | 说明 |
|---|---|
| 名称 | 必填，不超过 64 个字符 |
| 分组 | 可选，首页可按分组筛选 |
| 国家代码 | 两位字母，如 `HK`，用于国旗与地区筛选；留空则使用 Agent 探测的结果 |
| 仅登录可见 | 开启后该服务器不出现在公开页面与公开接口中，登录后可见 |
| 备注 | 仅后台可见，多行文本，不超过 2000 个字符 |

**计费**

| 字段 | 说明 |
|---|---|
| 价格 | 非负数字，可留空 |
| 币种 | 自由文本，如 `$`、`¥`、`USD` |
| 付费周期 | 不设置 / 月付 / 季付 / 年付 / 一次性 |
| 到期日 | 可留空表示长期（显示为 ∞）；7 天内到期会高亮提示 |

价格、币种、付费周期是否对访客公开，由设置中的「公开显示价格」控制。

**流量**

| 字段 | 说明 |
|---|---|
| 流量配额（GB） | 每个周期的配额，1 GB 按 1024³ 字节计；留空表示不限 |
| 计量方式 | 双向合计 / 仅入站 / 仅出站，决定「已用流量」的计算方式 |
| 重置日（1–28） | 每月该日 00:00（Dashboard 时区）开始新的流量周期，默认 1 |

月流量由 Dashboard 根据 Agent 上报的网卡累计计数计算，Agent 重启或计数器归零不会丢失已统计的流量。

**采集**

| 字段 | 说明 |
|---|---|
| 上报间隔（秒） | 1–60，留空使用设置中的默认上报间隔 |
| 仅统计网卡 | 填写后只统计名称以这些前缀开头的网卡 |
| 排除网卡 | 未填写「仅统计网卡」时生效：排除名称以这些前缀开头的网卡。留空使用内置列表（`lo`、`lo0` 以及 `tun`、`docker`、`veth`、`br-`、`vmbr`、`vnet`、`kube`、`vethernet`、`loopback` 前缀），填写后替换内置列表 |
| 排除挂载点 | 不计入磁盘统计的挂载点，同时排除其下的子路径，如 `/boot` |
| 不发送通知 | 开启后该服务器跳过全部通知规则（离线、高负载、到期、流量），不影响其他服务器 |

以上列表多个值用逗号分隔，网卡名匹配不区分大小写。修改网卡过滤后，月流量从新的统计口径继续累计，不会把口径变化造成的差值计入。

在线判定：Agent 连接存在，且最近一次上报距今不超过 3 倍上报间隔（最少 6 秒）。
